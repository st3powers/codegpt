Powers SM. Using ChatGPT to develop Shiny applications for rapid visualization of species occurrence databases.

Overview

Earth's biodiversity evolved over eons. Global change demands understanding of questions about the biosphere and all creatures in it. As a basic question: Where do different species occur? On the applied side: How can we develop a tool for visualizing species distributions? In an increasingly data-rich world, much evidence exists to address diverse biological questions and communicate evidence-based stories. The Global Biodiversity Information Facility (GBIF) serves a large and growing compilation of species location records from mostly crowdsourced data sources such as iNaturalist (iNat) and eBird across a tremendous diversity of life worldwide, with nearly 3 billion location records (and growing) as of April 2024. A recently released R package called 'spocc' aims to make these species occurrence data more accessible. To accelerate hypothesis formulation and evidence gathering relevant to changing species distributions, I used ChatGPT to support development of a simple Shiny application that successfully downloads and rapidly visualizes occurrence data from public databases for species chosen by the user. Secondary goals were to document and understand how ChatGPT code suggestions can vary for the same prompt, and which kinds of prompts lead ChatGPT to produce useful code vs. not useful code. To achieve these goals, I expanded on the ChatGPT conversation in example #7 "Write a shiny app" from the Supplementary of Merow et al. (2023), which uses R (R Core Team 2024). To start, I took the verbatim prompt from Merow et al. (2023), and entered it 12 times in independent chats to generate a range of ChatGPT responses for comparison. Each ChatGPT response was saved to a separate .txt file, and each code sequence generated was saved to a separate .R file. Every ChatGPT response included mostly logical code suggestions for development of the intended application, as well as errors that required troubleshooting. In response to a single prompt, one ChatGPT response stood out (#12, shinyap12.R) providing a complete script with coding suggestions that mostly addressed our intents with technical accuracy. For example, prior to any code revisions, this script successfully generated a leaflet basemap visualization within a shiny instance. In a single afternoon, I was able to inspect and successfully revise shinyapp12.R, making the code minimally functional. This functional code contains as few changes as possible from the original ChatGPT response, is coded in the script spocc_v1.R, and the associated app it creates is hosted publicly at https://waterfolk.shinyapps.io/spocc_minimal. Then in the same afternoon, I revised this minimalist spocc_v1.R script to satisfy my working objectives more closely, leading to spocc_v2.R and an associated app currently hosted at https://waterfolk.shinyapps.io/spocc. All files are shared at  https://github.com/st3powers/codegpt/tree/main/CaseStudy_shinyapp. This case study provides an example of how large language models can accelerate development of research workflows in biology and/or environmental science when supported through criticality, research questions, and reasonably specific goals and prompts. As a hypothesis, for both experienced and inexperienced developers of R code and Shiny applications, the speed of development of coded workflows at various levels of sophistication can increase by 10-fold or more with strategic use of large language models such as ChatGPT.
